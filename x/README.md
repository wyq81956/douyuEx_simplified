# X 附属脚本

版本 **1.1.2**，独立油猴脚本，默认屏蔽悬浮用户资料卡，并在视频推文右下角添加一键下载按钮，无需编译。1.1.2 增加播放前的视频预览、封面及已有媒体资料识别，避免必须点击播放才显示按钮。1.1.1 已修复将正常的 `a[role="link"]` 时间链接误判为引用区域、导致下载按钮不显示的问题，并兼容没有 `time` 元素、使用永久链接的详情布局。

## 安装与使用

1. 安装并启用 Tampermonkey。
2. 将同目录 [xex.user.js](xex.user.js) 的完整源码覆盖到已有 X 脚本中并保存；首次安装时在 Tampermonkey 中新建脚本。脚本名称、namespace 和原有资料卡开关存储键保持不变。
3. 如果篡改猴提示新增下载和连接权限，确认后刷新 X 页面。带普通视频的推文会在底部操作栏最右侧、“分享”之后显示 **下载** 按钮。
4. 点击 **下载**，保存网站提供的最高画质 MP4。按钮显示获取状态、下载进度和结果，失败时显示 **重试**，页面底部说明原因。

点击油猴图标 → **XEx：关闭用户资料卡屏蔽** 可关闭功能，并自动刷新页面；关闭后菜单变为 **XEx：开启用户资料卡屏蔽**。开关会在刷新和重启浏览器后保留。

视频下载使用独立开关，默认开启。油猴菜单的 **XEx：关闭视频下载按钮** 可关闭下载功能并自动刷新；关闭资料卡屏蔽不影响下载，关闭下载也不影响资料卡屏蔽。

当前版本供本地安装，尚未配置正式 Release 自动更新地址。

## 资料卡屏蔽

- 沿用 B站脚本的 CSS 思路，隐藏弹出的资料卡及外壳，而不逐一处理头像、昵称、用户名或周围热区。因此不同区域触发同一种资料卡时都能被隐藏。
- 精确匹配 `[data-testid="hoverCardParent"]` 和 `[data-testid="HoverCard"]`，保留页面上的头像、昵称、个人主页链接及点击操作，不隐藏整个弹层容器或通用提示框。
- 页面开始加载时注入 CSS，自动作用于后续异步加载、滚动追加和站内导航中新建的资料卡。
- 匹配 `x.com`、`www.x.com`、`mobile.x.com` 及对应的 `twitter.com` 地址，仅在顶层页面生效。
- 资料卡屏蔽不增加网络请求，不修改账号设置。页面自身可能仍请求资料卡数据，此功能只隐藏展示。

资料卡本体标识参考 [Control Panel for Twitter 作者源码](https://greasyfork.org/en/scripts/557621-control-panel-for-twitter/code)；外壳标识参考 [针对 X 悬浮资料卡的脚本作者说明及源码](https://note.com/zeroban_noriba/n/ne80c6be21f37)。已通过 JavaScript 语法和默认开启、关闭、重新开启的逻辑检查，用户于 2026-10-08 确认实际 X 页面试用正常；网站改版后可能需要调整选择器。

## 普通视频一键下载

- 仅给主帖本身带视频的推文添加按钮，放在底部操作栏最右侧；纯文字、纯图片或仅引用中有视频的推文不添加按钮。兼容滚动加载和站内导航，不重复添加；按钮点击不会打开推文详情。
- 播放前通过原生 `videoComponent` 预览外壳、X 视频封面图地址或页面已有的当前推文视频资料识别，不主动播放视频；新资料到达或封面地址变化时更新按钮，显示按钮本身不主动请求媒体数据。
- 旁读页面已发出的推文 API 响应，按当前推文 ID 缓存视频地址；优先选择最高码率 MP4，码率相同时按分辨率选择。只接受 `https://video.twimg.com/` 下的 MP4 地址，排除 `blob:` 和播放清单。
- 缓存缺失时，仅在点击下载后查询 X 的公开嵌入接口 `cdn.syndication.twimg.com/tweet-result`。该请求不附带账号 Cookie，也不使用第三方解析网站；嵌入接口可能无法返回受保护或部分受限制推文，此时提示重试。
- 通过篡改猴的 `GM_download` 保存，文件名为 `x_推文ID_序号.mp4`。一条推文有多个视频时顺序下载全部视频；GIF 动画若以 MP4 提供，也保存为 MP4。不另下图片。
- 本版只处理现成的完整 MP4。只有 HLS 分段流、直播、引用视频等暂不支持；没有完整 MP4 时显示提示，不将清单文件伪装成视频。
- 下载由浏览器保存到其配置的下载目录，是否弹出另存为窗口由浏览器设置决定。若提示下载权限错误，请检查篡改猴设置中的下载功能及 `.mp4` 扩展名许可。

公开嵌入接口、token 和媒体结构参考 [Vercel react-tweet 的接口实现](https://github.com/vercel/react-tweet/blob/main/packages/react-tweet/src/api/fetch-tweet.ts) 和 [媒体类型定义](https://github.com/vercel/react-tweet/blob/main/packages/react-tweet/src/api/types/media.ts)。没有外部脚本依赖，不修改账号设置或播放器状态。

运行 `node tests/x-download.test.cjs` 可检查播放前的预览外壳和封面识别、仅收到媒体资料时自动添加按钮、普通图片和引用封面过滤，以及时间链接识别、按钮位置和去重、最高码率选择、fetch/XHR 缓存、公开接口回退、多视频、引用和回复隔离、分段流提示、列表复用、失败重试及独立开关。1.1.1 的回归检查先重现了 1.1.0 不显示按钮的情况，修复后全部通过；用户已确认 1.1.1 在实际页面播放后能显示按钮。1.1.2 的检查先重现了播放前不显示的情况，修复后全部通过。按钮位置及模拟下载完成状态已在本地浏览器预览中确认；1.1.2 播放前的实际展示和文件保存效果仍待试用。
